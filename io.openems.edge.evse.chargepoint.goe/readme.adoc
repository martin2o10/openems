= EVSE Charge-Point go-e

Implementation for the go-e Gemini charging station via Modbus/TCP.

https://github.com/OpenEMS/openems/tree/develop/io.openems.edge.evse.chargepoint.goe[Source Code icon:github[]]

== Supported devices

- go-e Gemini (flex)
- go-e Modbus TCP API v2; the read-only register PHASE_SWITCH_MODE requires firmware >= 55.5

== Communication

This component communicates via Modbus/TCP on port 502. The Modbus interface
must be enabled first: in the go-e App under "Internet" -> "Erweiterte
Einstellungen" -> "Modbus", or via the HTTP API key `men=true` (a restart of
the charge point is required).

- Reads use Modbus function code 3 (Holding Registers) and 4 (Input
Registers).
- Writes use function code 16 only. Function code 6 is not supported by go-e,
even for single registers.
- The EEPROM register 40301 (AMPERE_EEPROM) is never written: it tolerates
only ~100.000 write cycles. Charging regulation uses the volatile register
40300 (299, AMPERE_VOLATILE) instead.
- Multi-register values (uint32) are read with low word first (word order
LSWMSW), as documented by go-e ("Big Endian (Word Swap)"). The go-e API keys
`msb` (swap bytes) and `msr` (swap registers) must remain disabled.

== Features

- Reading of meter values (voltage, current, power, energy), car state and
error state
- Setting the charging current via AMPERE_VOLATILE (register 299) with
write-on-change: identical set-points are not written again
- Enable-on-charge via the ALLOW register (200): the transition from 0 to a
set-point greater than zero writes ALLOW=1 once, returning to zero writes
ALLOW=0. A set-point of zero does not write the current register, because it
accepts only 6..32 A
- The advertised maximum charging current is the configured value limited by
the hardware maximum current (register 211, e.g. 16 A for the 11 kW variant)
- Session energy (ENERGY_CHARGE) is provided as EvseGoe.ENERGY_SESSION in
[Wh]

== Known limitations

- Phase switching is out of scope. PHASE_SWITCH_MODE (register 332) is read
for diagnostics only and never written; no phase-switch ability is
advertised
- AMPERE_EEPROM (register 40301) is never written (EEPROM wear, ~100.000
write cycles)
- The real FC16 write transactions are executed on the Modbus bridge; unit
tests cover the write-decision logic (queued write values), not the bridge
communication itself

== Hardware verification status

The register mapping follows the go-e Modbus TCP API v2 documentation
(modbus-de.md). It has not been verified on real hardware yet. Planned
verification points:

- uint32 word order (assumed low word first, see Communication)
- ALLOW register vs. FORCE_STATE interplay
- ERROR register value 0 (interpreted as "no error")
- ENERGY_CHARGE (Deka-Watt-seconds to Watt-hours)
- PHASES bit layout (0b00ABCDEF, phases before/after the contactor)
- Modbus Unit-ID (go-e Modbus interface is documented without Unit-ID
selection; default 1 is assumed)
